# shap-rs implementation tracker

This file is the source of truth for remaining work. Check an item only after
its implementation, documentation, and proportionate tests are complete.

Last verified baseline: 92 unit tests, 5 doctests, all features, strict Clippy,
warning-free rustdoc, and `cargo package` verification pass.

## Implemented foundation

- [x] Unified `Predict`, `Masker`, `Explainer`, and `Explanation` architecture
- [x] Dense multi-sample and multi-output `ndarray` representation
- [x] Background distributions and fixed/independent/closure maskers
- [x] Numeric text-token and flattened-image maskers
- [x] Feature/output metadata and automatic metadata decoration
- [x] Identity and logit links across model-agnostic coalition explainers
- [x] Additivity checking with absolute and relative tolerances
- [x] Deterministic per-sample RNG and antithetic permutation sampling
- [x] Batched coalition evaluation, deduplication, row budgets, and bounded LRU caching
- [x] Serde validation and versioned JSON explanations/interactions
- [x] Optional Rayon execution with chunk-invariant stochastic results
- [x] Exact, Kernel, Permutation, Sampling, and Auto explainers
- [x] Independent and Gaussian-correlated Linear SHAP
- [x] Flat and hierarchical Partition/Owen values and correlation clustering
- [x] Native polynomial TreeSHAP with repeated-feature and missing-value handling
- [x] Polynomial exact TreeSHAP interaction values
- [x] Exact model-agnostic interaction values
- [x] Expected Gradients with uncertainty estimates
- [x] Deep SHAP adapter contract and validation coordinator
- [x] Additive-model and DAG-constrained causal explainers
- [x] Native tree ensembles plus XGBoost-dump and LightGBM-dump importers
- [x] Plot-ready bar, waterfall, force, beeswarm, scatter, heatmap, and decision data
- [x] Standalone dependency-free SVG renderers for the main plot families

## P0 — correctness and compatibility before a stable release

- [ ] Build committed reference fixtures generated by Python SHAP for Exact,
      Kernel, Permutation, Partition, Linear, Tree, and interaction values.
- [ ] Cross-check binary, multiclass, multi-output regression, missing values,
      repeated tree splits, nonuniform covers, and logit-link explanations.
- [ ] Add end-to-end XGBoost compatibility fixtures from real trained models,
      including regression, binary classification, multiclass ordering, base
      score/base margin handling, tree weights, and missing defaults.
- [ ] Add end-to-end LightGBM compatibility fixtures from real trained models,
      including regression, binary classification, multiclass ordering,
      learning-rate-adjusted leaves, and missing defaults.
- [ ] Decide and document numerical tolerances per algorithm and platform.
- [ ] Audit every public serde type for constructor-bypass safety; prefer custom
      validated deserialization where use-time validation is insufficient.
- [ ] Add overflow/allocation guards for every shape derived from user input.

## P1 — tree ecosystem completeness

- [ ] Support LightGBM categorical splits and categorical missing-value rules.
- [ ] Support additional XGBoost JSON model schemas, not only recursive dumps
      produced with statistics enabled.
- [ ] Represent split comparison semantics explicitly (`<`, `<=`, categorical)
      instead of normalizing strict thresholds to the previous `f64`.
- [ ] Add interventional TreeSHAP using a supplied background distribution.
      Current native TreeSHAP is tree-path-dependent.
- [ ] Add tree output transformations for probability and log-loss explanation
      where mathematically supported; raw-margin output remains the baseline.
- [ ] Add per-tree output-group metadata instead of relying on round-robin tree
      ordering assumptions in imported multiclass dumps.
- [ ] Add a SmartCore adapter when SmartCore exposes stable public tree-export
      data. Its current model internals are private; `TreeArrays` is the safe
      interoperability boundary until then.
- [ ] Consider adapters for additional Rust tree libraries after their public
      tree/cover/missing-routing APIs are verified.

## P1 — scalable model-agnostic explanations

- [ ] Add sparse input/background support without densifying every coalition.
- [ ] Add grouped-feature masking where one coalition bit controls multiple
      original columns while explanations retain group and source metadata.
- [ ] Add native categorical/tabular maskers and conditional samplers.
- [ ] Add approximate hierarchical Owen sampling for hierarchies whose exact
      hierarchy-consistent permutation count exceeds the configured limit.
- [ ] Add streaming/out-of-core background evaluation.
- [ ] Add reusable cross-sample model-evaluation caching where model and masker
      semantics make it safe.
- [ ] Evaluate a numerically stronger optional linear algebra backend for large
      Kernel SHAP weighted least-squares systems.

## P2 — structured and causal masking

## Definition of “complete enough for 1.0”

- [ ] P0 compatibility fixtures pass on every supported platform.
- [ ] Tree import limitations and explainer semantics are explicit and tested.
- [ ] Every advertised advanced integration has at least one concrete adapter;
      contracts without implementations are labeled experimental.
- [ ] Public deserialization and indexing APIs cannot panic on malformed input.
- [ ] CI, benchmarks, fuzzing, examples, and release documentation are present.
- [ ] The public API has completed a semver-focused review.
